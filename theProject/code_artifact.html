١ ماهية تطبيق الويب (كتاب الوزارة ص 51) What is a Web Application? (Textbook p. 56)

📌 تعريف تطبيق الويب (Web Application):📌 Web Application Definition: هو برنامج أو تطبيق يُستخدم من خلال متصفح الويب (مثل Chrome أو Edge أو Safari)، ويمكن استخدامه مباشرة طالما يتوفر لديك متصفح، دون الحاجة إلى تثبيت برامج مخصصة على جهازك. A software application accessed and operated through a web browser. It can be used instantly as long as a browser is available, without requiring dedicated software installation.

🌟 أمثلة يومية بارزة من كتاب الوزارة:🌟 Everyday Real-World Examples: موقع مشاركة الفيديو (YouTube)، منصات التسوق والتجارة الإلكترونية (Amazon)، خدمات البريد الإلكتروني (Gmail)، وخدمات الخرائط الملاحية (Google Maps). Video sharing platforms (YouTube), e-commerce marketplaces (Amazon), webmail clients (Gmail), and interactive mapping tools (Google Maps).

الحقيقة الجوهرية (Key Fact - كتاب الوزارة): Core Principle (Key Fact):

كل تطبيق ويب يتكون في جوهره من ثلاث طبقات متعاونة: الواجهة التي يتفاعل معها المستخدم مباشرة في المتصفح، الخادم البعيد الخفي الذي يعالج الطلبات والقرارات، وقاعدة البيانات التي تخزن السجلات والبيانات وتوفرها عند الحاجة. Every web application is engineered upon three cooperating tiers: the frontend user presentation in the browser, the remote backend server enforcing business rules, and the database organizing persistent records.

٢ الطبقات الثلاث لتطبيق الويب (ص 51 - ص 52) The Three Tiers of a Web Application (pp. 56 - 57)

Frontend • Backend • Database
١. الواجهة الأمامية 1. Frontend (Client) العرض والتفاعل

مكون الشاشة الذي يراه المستخدم ويتعامل معه مباشرة. يعمل داخل متصفح الويب، ويعرض المحتوى المرئي، ويستقبل مدخلات ونقرات المستخدم. The presentation component that users directly see and interact with. Runs in the web browser, displays UI, and collects user input.

أمثلة:Examples: شاشات البحث، صفحات عرض المنتجات، نماذج إدخال البيانات، وسلة التسوق.
٢. الواجهة الخلفية 2. Backend (Server) المعالجة والتحكم

المعالجة البرمجية الخفية التي لا يراها المستخدم. تعمل على جانب خادم الويب، وتستقبل الطلبات، وتطبق منطق وقواعد العمل، وتتخذ القرارات البرمجية. The server-side business logic engine unseen by users. Processes requests, executes algorithmic rules, verifies logins, and decides outcomes.

أمثلة:Examples: البحث عن المنتجات المطابقة، التحقق من كلمات المرور، فحص توفر المخزون، وتنفيذ عمليات الدفع.
٣. قاعدة البيانات 3. Database Tier التخزين والإدارة

النظام المخصص لـ تنظيم وتخزين وإدارة البيانات بشكل دائم وآمن. يسترجع السجلات عند الحاجة ويسجل البيانات والعمليات الجديدة. Dedicated persistent data storage and query system. Indexes, retrieves, and updates records on demand across relational tables or data stores.

أمثلة:Examples: بيانات المنتجات والأسعار، سجلات المستخدمين، سجل المشتريات، والرسائل.

العميل مقابل الخادم (Client vs Server): Client vs Server Architecture:

• العميل (Client): الجانب الذي يطلب البيانات أو المعالجة من الخادم. تندرج متصفحات الويب (Web Browsers) وتطبيقات الهواتف الذكية ضمن هذه الفئة.

• الخادم (Server): الجانب الذي يستقبل الطلبات من العملاء، ويعالجها برمجياً، ثم يرجع الاستجابات (Responses) المناسبة.

• دورة الطلب والاستجابة: يعمل تطبيق الويب بالكامل عبر إرسال العميل طلباً (Request)، وإرجاع الخادم استجابة (Response).

مقارنة الأمان: HTTP مقابل HTTPS: HTTP vs HTTPS Security Comparison:

• بروتوكول HTTP (HyperText Transfer Protocol): بروتوكول اتصال أساسي لتبادل البيانات، لكنه ينقل البيانات بنص صريح (Plaintext) غير مشفر، مما يجعله عرضة للتنصت والاعتراض.

• بروتوكول HTTPS (HTTP Secure): بروتوكول اتصال يضيف تشفير TLS (Transport Layer Security) إلى بروتوكول HTTP. يساعد على حماية سرية الاتصال وسلامته، ومصادقة هوية الخادم، فلا يستطيع المتنصت قراءة البيانات أو تعديلها أثناء النقل.

🔒 المواقع التي تبدأ عناوينها بـ "https://" تستخدم اتصال HTTPS الآمن، وتظهر قفلاً أخضر بجانب شريط العنوان.

جـ المصطلحات والمفاهيم العلمية المقررة بالوحدة الثالثة Key Scientific Terms Defined

1. تطبيق الويب (Web Application):

تطبيق يُستخدم من خلال متصفح الويب دون الحاجة إلى تثبيت برمجيات مخصصة على جهاز المستخدم.

2. الواجهة الأمامية (Frontend):

مكون الشاشة الذي يراه المستخدم ويتعامل معه مباشرة داخل المتصفح، يتولى عرض المحتوى واستقبال المدخلات.

3. الواجهة الخلفية (Backend):

المعالجة البرمجية التي تعمل على جانب الخادم بعيداً عن رؤية المستخدم، وتتولى معالجة البيانات وتطبيق قواعد التطبيق.

4. قاعدة البيانات (Database):

نظام ينظم ويخزن ويدير البيانات، ويسترجعها عند طلب الخادم ويسجل العمليات الجديدة.

5. واجهة برمجة التطبيقات (API):

مجموعة قواعد وبروتوكولات واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر وتبادلها بسرعة.

6. صيغة JSON (JavaScript Object Notation):

صيغة نصية قياسية خفيفة وسهلة القراءة لتبادل البيانات المنظمة بين العميل والخادم باستخدام المفاتيح والقيم.

7. HTML الدلالية (Semantic HTML):

استخدام وسوم توضح المعنى والوظيفة البنائية لأجزاء الصفحة (مثل header و nav و main و footer) لتحسين الوصول وقراءة الشاشة و SEO.

8. التصميم المتجاوب (Responsive Design):

مفهوم تصميمي يضبط تخطيط وأبعاد صفحة الويب تلقائياً لتناسب مختلف مقاسات الشاشات من هواتف ذكية إلى حواسيب مكتبية.

• مفهوم تطبيق الويب:Web App: تطبيق يُستخدم عبر المتصفح دون تثبيت برامج (YouTube, Amazon, Gmail).

• الطبقات الثلاث:Three Tiers: 1) الواجهة الأمامية (Frontend): العرض وتفاعل المستخدم في المتصفح. 2) الواجهة الخلفية (Backend): المعالجة وتطبيق قواعد العمل على الخادم. 3) قاعدة البيانات (Database): تخزين وإدارة السجلات واسترجاعها.

• طرق الطلب:HTTP Methods: GET لاسترجاع البيانات وعرض الصفحات؛ و POST لإرسال البيانات الحساسة ونماذج الدخول.
